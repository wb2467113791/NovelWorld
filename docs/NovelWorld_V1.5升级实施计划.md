# NovelWorld V1.5 升级实施计划

> 本文是 [`NovelWorld_两周学习计划_V1及升级路线.html`](NovelWorld_两周学习计划_V1及升级路线.html) 中 V1.5 路线的实施拆解；原文件仍是学习计划的唯一来源。作者本轮要求直接完成 V1.5，因此本轮合并实施并统一验收。

## 目标与当前起点

V1.5 用约 1–2 周解决两个问题：角色经历超过近期窗口后会遗忘；世界设定不能无限塞进 Prompt。最终让角色从**自己的长期记忆**和**允许知道的世界设定**中按需取回少量相关内容，同时保留 V1 的工具规则和独立信息视角。

升级前的起点：`v1.0` 已打标签；`main` 上又增加了调查事实校验和单 Tick 行动限制。那时 `ShortTermMemory` 只保留最近 5 条，旧条目被直接丢弃；Reflection（反思）也只看这个窗口。Prompt 直接加入近期记忆和角色的全部 `known_facts`，还没有检索层。项目虚拟环境下的升级前基线为 91 项测试通过。

## 设计边界

- **Working Memory（工作记忆）**：当前 Tick 的目标、工具观察和少量近期经历；继续由 `AgentState` 与短期窗口承载。
- **Episodic Memory（情节记忆）**：某角色亲历或感知的事件摘要，带角色、事件来源、时间、重要性和标签。超出工作窗口也保留；角色之间不能互查。
- **Semantic Memory（语义记忆）**：从已验证事件归纳出的稳定事实。先定义来源和更新规则，再加入自动归纳；不能把模型猜测当成事实。
- **Relationship Memory（关系记忆）**：`Character.relationships` 仍是当前关系值的唯一真实来源。检索可返回过去的交往事件，但不另存一份可相互矛盾的“当前关系值”。
- **Reflection（反思）**：基于新增的本人经历生成，并记录处理进度，避免近期窗口淘汰造成遗漏或重复反思。反思是解释，不直接修改世界状态。
- **World Lore（世界设定）**：地理、势力、历史、规则使用独立资料与索引，标出公开范围。角色私有秘密不得放进公共设定检索。

模型负责根据提供的上下文选择行动和工具；Python 负责事件感知、访问过滤、检索、规则校验与状态修改。检索结果只是可供模型参考的信息，不代表新的世界事件已发生。

## 检索与可信度规则

1. 写入时只保存相关角色实际感知到的事件摘要，并保留来源事件 ID。不要把所有世界事件广播给所有 NPC。
2. 检索时先执行角色与公开范围过滤，**再**计算相似度、时间和重要性；不能指望模型读到秘密后自行忽略。
3. 近期记忆与长期召回去重，结果标明“近期经历 / 历史经历 / 世界设定 / 反思”。限制条数或字符数，避免 Prompt 随 Tick 无限增长。
4. 事件和 `World State` 是事实依据。语义摘要或反思与最新状态冲突时，以结构化事件和当前状态为准。
5. 向量索引可删除并从受控来源重建；记录 ID 必须稳定，便于去重和更新。
6. 同一世界的状态、事件、记忆和反思进度必须一起保存与恢复；Chroma 只充当检索索引。新世界使用新的世界 ID，不能混入旧世界的私有记忆。

## 技术选择与费用

V1.5 计划使用**本地 Chroma**：它提供本地持久化客户端和元数据过滤，适合本项目先在单机学习检索。真正接入前需确认当前 API、依赖与 Windows 环境兼容性；如兼容性有障碍，再讨论替代方案。参考：[Chroma Python Client](https://docs.trychroma.com/reference/python/client)、[元数据过滤](https://docs.trychroma.com/docs/querying-collections/metadata-filtering)。

V1.5 使用本地 Chroma 与纯 Python 字符片段哈希向量；无需下载嵌入模型，也不调用付费 Embedding API。同义词或隐含语义的召回能力有限。自动测试与离线对照均不调用模型 API；真实模型手动测试可能产生费用。

## V1.5 完成标准

- 三名 NPC 连续运行后，相关旧经历仍能按需找回，近期 Prompt 不随历史长度持续膨胀。
