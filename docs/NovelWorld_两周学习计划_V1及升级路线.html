NovelWorld：会自己“活下去”的小说世界

目标不是做 AI 聊天角色，而是做一个 动态叙事世界引擎：角色拥有目标、记忆、关系和独立信息视角，会调用工具改变世界状态，并在多智能体交互中自然产生剧情。

PythonLangGraphTool Calling MemoryRAGMulti-Agent MCPAgent SkillsSpring Boot

1. 项目定位：不要做“AI 写小说”

一句话定位：基于 Multi-Agent、长期记忆与世界状态驱动的动态叙事引擎。
V1让 3 个 NPC 会自己行动、交流、改变关系和世界状态。
V2加入长期记忆、RAG、MCP、Spring Boot，让架构工程化。
V3加入 Skills、Director、实时 Web UI 和 Eval，成为简历主项目。

核心不是“故事写得多好”，而是你是否真正处理了 Agent State、Memory、Tool、Context、Multi-Agent 协作、外部能力标准化和评测。

3. 两周开发原则

必须做两周内先不做
3 个 NPC、Goal、短期 Memory、独立 Knowledge、Tool Calling、World State、多 Agent Tick、基础剧情日志 MCP、复杂 RAG、向量库、Redis、MySQL、完整 Web UI、复杂 Director、账号系统、K8s、微服务

V1 成功标准：启动世界后，即使用户不输入，三个角色也会根据自身目标和已知信息采取行动，并让关系、位置、事件和记忆持续变化。

6. V1 之后怎么升级

V1.5｜Long-term Memory + RAG（约 1–2 周）

真实问题：角色经历越来越多，近期窗口装不下；世界设定也不能全塞 Prompt。

  • Memory 分层：Working / Episodic / Semantic / Relationship / Reflection。
  • Retrieval：recency + importance + similarity。
  • World Lore RAG：地理、势力、历史、规则独立检索。
  • Memory RAG 和 Knowledge RAG 分开。
  • Vector DB 选一个：Qdrant / pgvector / Chroma。

V2｜Spring Boot + MySQL / Redis + MCP（约 2 周）

真实问题：Python Agent Runtime 不该直接承担全部业务和持久化。

  • Spring Boot：World / NPC / Event / Save / Inventory / Relationship。
  • MySQL：持久化；Redis：World State、session、event queue、热状态。
  • Java 侧实现 MCP Server，暴露地图、人物、物品、时间、事件能力。
  • Python 侧 MCP Client 调用世界能力。
Python Agent Runtime
        │
      MCP Client
        │
Spring Boot MCP Server
        │
 MySQL / Redis

V2.5｜Agent Skills（约 1 周）

真实问题：不同职业需要不同程序性知识，全部塞 System Prompt 会膨胀。

skills/
  investigation/SKILL.md
  negotiation/SKILL.md
  trading/SKILL.md
  deception/SKILL.md
  survival/SKILL.md
  • Skill Router：按角色职业 + 当前任务选 Skill。
  • Progressive Disclosure：只加载当前需要的 Skill。
  • Skill 可携带 instructions / scripts / resources。

V3｜Director Agent + Web UI + 实时事件流（约 2–3 周）

真实问题：完全自由的 NPC 容易无聊、重复、失去节奏。

  • Director 只施加世界事件，不直接控制 NPC 行为。
  • 检测 stagnation / conflict / participation。
  • Vue/React + SSE/WebSocket 展示 Timeline、NPC 状态、关系图、Memory。
  • 支持暂停、单步 Tick、加速、查看角色视角。

V3.5｜Eval / Ablation

  • 无 Memory vs Short Memory vs Retrieval Memory。
  • 无 Director vs Director。
  • 全量 Prompt vs RAG。
  • 统计一致性、信息泄漏、重复率、Token、延迟。

8. 面试时必须会讲的 12 个问题

1. Tool Calling 到底是谁执行 Tool？
2. Agent Loop / LangGraph State 是什么？
3. World State 为什么不能只放 Prompt？
4. 怎么防止 NPC 使用自己不知道的信息？
5. Memory 什么时候写、写什么、属于谁？
6. 为什么 Long-term Memory 需要 Retrieval？
7. Memory RAG 和 World Knowledge RAG 有什么区别？
8. 为什么用 MCP，而不是全写本地 Tool？
9. Tool、Skill、MCP 各自是什么层次？
10. Multi-Agent 如何避免无限聊天和成本爆炸？
11. Director 如何不破坏 NPC 自主性？
12. 如何量化“剧情一致性”和 Agent 质量？

9. 最终简历写法

NovelWorld｜基于 Multi-Agent 与长期记忆的动态叙事世界引擎

  • 基于 LangGraph 构建多智能体运行时，为 NPC 建立独立 Goal、Knowledge、Memory 与 Relationship State，实现角色基于世界事件自主规划、工具调用和状态更新。
  • 设计分层长期记忆与双路检索体系，将 Episodic Memory 与 World Lore 分离，通过 Retrieval 控制上下文长度并减少角色知识泄漏。
  • 基于 Spring Boot 构建世界状态服务，并通过 MCP Server 暴露地图、人物、物品和事件等标准化能力，实现 Python Agent Runtime 与 Java 业务层解耦。
  • 设计 Agent Skills 动态加载机制和 World Rule Guardrail，并通过 Knowledge Leakage、Goal Consistency、Invalid Action 等指标构建 Agent Eval。

只有真实做完对应版本后，再把对应条目写进简历。
